### Inferred Business Meanings

| Column | Inferred Meaning | Evidence |
|--------|-----------------|---------|
| `date` / `date_initiated_by_firm` | **Event occurrence/initiation date** — when the recall/safety action was initiated | Mutually exclusive; used by different regulatory bodies for the same concept |
| `date_posted` | **Public posting date** — when the recall/safety notice was made public by the authority | Present in USA (85.5%), CHE (100%), GBR (72.8%), HKG (81.4%); always equal to or later than initiation date |
| `date_terminated` | **Recall closure date** — when the recall action was completed/terminated | Almost exclusively USA (31,293 / 31,487 = 99.4%); correlates with `status = "Terminated"` |
| `date_updated` | **Record update date** — when the regulatory record was last updated | Extremely sparse (231 records, 0.2%); not usable |
| `create_date` | **Database record creation date** — when the event was entered into the originating database | Very sparse (5,201 records, 4.2%); concentrated in 2015–2018 |

### Temporal Timeline Viability Assessment

| Question | Answer |
|----------|--------|
| Can a reliable event date be constructed? | **Yes**, for 93.2% of events, by coalescing `date_initiated_by_firm` > `date` > `date_posted` > `create_date` |
| Are outliers a problem? | **No** — only 11 records out of 116,525 dated events fall outside 1990–2025; trivially filterable |
| Is there a systemic date-quality concern? | **Yes** — 6.8% of events (8,444) have no date at all, primarily from Sweden (3,469) and partially from Ireland (3,140). These events cannot be placed on a timeline |
| Can temporal ordering be established? | **Partially.** For the 93.2% of events with dates, yes. For the 3,576 multi-event devices, temporal ordering is possible but with caveats: 943 multi-event devices have all events on the same date (span = 0 days), meaning temporal ordering within a device is not always distinguishable |
| Is the date range suitable for temporal train/test splits? | **Yes**, the 1991–2019 range with bulk in 2007–2018 provides a sufficient timeline, though most devices have only 1 event so per-device temporal rolling is limited to the 3.03% with multiple events |
| Do different date columns conflict? | **No** — they are complementary (country-specific), not contradictory |

### Undateable Events — Risk for Stage 3
